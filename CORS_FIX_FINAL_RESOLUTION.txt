## Why This Error Occurred

The frontend code sends the `ngrok-skip-browser-warning` header to suppress ngrok's browser warning modal. This is a security-related custom header that needs to be explicitly allowed by the backend's CORS configuration.

When a browser makes a fetch request with a custom header:
1. Browser first sends OPTIONS (preflight) request
2. Backend responds with which headers it allows
3. If the header is not in `Access-Control-Allow-Headers`, browser blocks the request
4. JavaScript gets: "Request header field X is not allowed by Access-Control-Allow-Headers"

**Solution:** Add the header name to the backend's CORS allow-headers list.

## CORS Header Explanation

### What Each Header Does

- **Access-Control-Allow-Origin: ***
  - Allows requests from any origin
  - Needed for localhost and file:// protocol

- **Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS, PATCH, HEAD**
  - Specifies which HTTP methods are allowed
  - OPTIONS is required for preflight

- **Access-Control-Allow-Headers: Content-Type, Authorization, Accept, X-Requested-With, Cache-Control, Pragma, ngrok-skip-browser-warning**
  - Lists which custom headers browser is allowed to send
  - **ngrok-skip-browser-warning** is the header that was missing

- **Access-Control-Max-Age: 86400**
  - Browser caches this preflight response for 24 hours
  - Reduces number of OPTIONS requests

### Response Code: 204 No Content
- Proper HTTP status for OPTIONS requests
- Indicates successful preflight check
- Browser then proceeds with actual GET/POST request
