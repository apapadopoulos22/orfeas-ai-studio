1️⃣ PHASE4_CACHE_MANAGER.PY (360 lines)
   ──────────────────────────────────────

   Purpose: Redis-backed caching with in-memory fallback

   Key Classes:
   • CacheManager (facade/singleton)
     - get(key): Retrieve cached value
     - set(key, value, ttl): Store value with TTL
     - delete(key): Remove cached value
     - flush(): Clear all cache
     - stats(): Get cache statistics

   • RedisCache (persistent backend)
     - Uses Redis connection
     - Automatic JSON serialization
     - Full error handling

   • InMemoryCache (fallback backend)
     - Dictionary-based storage
     - TTL-based expiration
     - Thread-safe operations

   Key Decorators:
   • @CacheManager.cache_response(ttl, key_prefix)
     - Automatic function result caching
     - Decorator pattern for easy integration
     - Configurable TTL and cache key prefix

   Usage Example:
     cache = get_cache_manager(use_redis=False)
     cache.set('key', {'data': 'value'}, ttl=300)
     value = cache.get('key')

   Features:
   ✓ Two-tier architecture (Redis + fallback)
   ✓ Automatic TTL expiration
   ✓ Cache statistics
   ✓ Memory-efficient
   ✓ Thread-safe operations
   ✓ Singleton pattern

3️⃣ PHASE4_RATE_LIMITER.PY (320 lines)
   ───────────────────────────────────

   Purpose: Token bucket rate limiting algorithm

   Key Classes:
   • TokenBucket (algorithm implementation)
     - refill(): Refill tokens based on elapsed time
     - consume(tokens): Try to consume tokens
     - get_tokens(): Current token count
     - reset(): Reset to full capacity

   • RateLimiter (request limiter)
     - is_allowed(key, requests_per_minute): Check if allowed
     - get_status(key): Get current status
     - reset_key(key): Reset rate limit
     - get_all_stats(): All rate limit statistics

   Algorithm: Token Bucket
   • Fixed capacity (requests_per_minute)
   • Tokens refill continuously
   • Smooth refill rate (no bursts)
   • Per-key tracking

   Usage Example:
     limiter = get_rate_limiter()
     allowed, remaining = limiter.is_allowed("user_123", 100)
     if allowed:
         # Process request
         pass
     else:
         # Return 429 Too Many Requests
         pass

   Features:
   ✓ Token bucket algorithm (proven, standard)
   ✓ Per-key quotas
   ✓ Smooth refill (no burst penalties)
   ✓ Real-time status
   ✓ Resettable limits
   ✓ Statistics tracking

   Purpose: Input validation and sanitization

   Key Methods:
   • validate_discipline_id(value) → str or None
     - Checks: length (max 100), injection patterns
     - Returns: Cleaned value or None if invalid

   • validate_search_query(value) → str or None
     - Checks: length (max 200), injection patterns
     - Returns: Cleaned value or None if invalid

   • validate_tier_number(value) → int or None
     - Checks: 1-12 range, numeric format
     - Returns: Integer 1-12 or None

   • validate_pagination_params(limit, offset) → dict or None
     - Checks: limit (1-100), offset (≥0)
     - Returns: {limit, offset} or None

   • validate_query_type(value) → str or None
     - Checks: pathfinding, related, semantic_search, tier_analysis
     - Returns: Valid type or None

   • validate_query_params(query_type, params) → dict or None
     - Validates parameters for specific query type
     - Returns: Validated params or None

   • sanitize_string(value, max_length) → str
     - Removes null bytes, control chars
     - Truncates to max_length
     - Returns: Sanitized string

   Attack Detection:
   • SQL Injection Patterns
     - Keywords: SELECT, INSERT, UPDATE, DELETE, DROP, UNION
     - Operators: =, ;, --, /*, */
     - Procedures: xp_, sp_, exec, execute

   • XSS Patterns
     - HTML Tags: <script>, <iframe>, <object>
     - Event Handlers: onerror, onclick
     - JavaScript: javascript:, eval(), expression()

   Features:
   ✓ SQL injection prevention
   ✓ XSS attack prevention
   ✓ Type validation
   ✓ Length limits
   ✓ Range checking
   ✓ Pattern matching

5️⃣ PHASE4_SECURE_APP.PY (450 lines)
   ────────────────────────────────

   Purpose: Enhanced Flask application with security middleware

   Key Function:
   • create_secure_app(config) → Flask app
     Returns: Fully configured Flask application

   Decorators:
   • @require_api_key
     - Validates X-API-Key header
     - Sets request.api_key_id and request.api_key_data
     - Returns 401 if invalid

   • @check_rate_limit
     - Enforces rate limiting
     - Adds X-RateLimit-* headers
     - Returns 429 if exceeded

   New Endpoints:
   • GET /api/health
     - Public health check
     - No authentication required

   • GET /api/security/health
     - Verify authentication
     - Returns security status

   • GET /api/security/stats
     - Detailed security statistics
     - Cache, auth, rate limiter data

   • GET /api/security/keys
     - List all API keys
     - Shows metadata (masked keys)

   • POST /api/security/keys
     - Create new API key
     - Body: {name, scopes[], rate_limit}

   Security Headers (Automatic):
   • X-Content-Type-Options: nosniff
   • X-Frame-Options: DENY
   • X-XSS-Protection: 1; mode=block
   • Strict-Transport-Security: max-age=31536000
   • Content-Security-Policy: default-src 'self'

   Features:
   ✓ Automatic CORS configuration
   ✓ Request validation
   ✓ Rate limiting
   ✓ Security headers
   ✓ Error handling
   ✓ Request logging
